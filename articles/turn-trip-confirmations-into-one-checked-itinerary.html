Turn Trip Confirmations Into One Checked Itinerary

OpenRouter’s Free Models Router turns pasted, redacted booking details into a source-tagged timeline and conflict checklist. It is free forever with no card, but the free plan is capped at 50 requests per UTC day and 20 per minute; the responding model can change from one request to the next.

Numbered walkthrough

Build the itinerary, then check it

The first pass extracts. The second pass audits. Only after those passes do you add dated information from an official source.

Step 1 of 6 Prepare
Step 01

Make one redacted source pack

Copy the useful text from each flight, rail, hotel, rental, or event confirmation into a note. Label each block Source A, Source B, and so on. Remove passport numbers, payment details, loyalty numbers, booking links with private tokens, and confirmation codes. Keep dates, printed local times, time-zone labels, supplier names, station or airport codes, addresses, baggage rules, and cancellation deadlines.

Do not upload a whole inbox. A smaller source pack is easier to audit and gives a rotating free model fewer chances to mix unrelated details.

Step 02

Select the no-cost router

Create an OpenRouter account; the free plan does not require a payment method. Open openrouter.ai/chat, choose Add Model, search for “free,” and select Free Models Router. Check the picker before sending: a similarly named paid model is not the same route.

After each answer, note the model name shown by the chat. The router selects from available free models, so a later request may use a different model and phrase the output differently.

Step 03

Compile facts without adding travel claims

Paste this prompt, then replace the bracketed area with the redacted source pack. It forces a distinction between text that appeared in a confirmation and details the model cannot find.

Itinerary compiler prompt
Act as an itinerary compiler, not a travel search engine.

RULES
- Use only the source blocks I provide.
- Do not invent or complete missing facts.
- Preserve each date, local time, time-zone label, airport/station code, address, and deadline exactly as printed.
- Tag every factual row [CONFIRMED FROM INPUT], [MISSING], or [CONFLICT].
- If two sources disagree, quote both values and their source labels.

OUTPUT
1. A source ledger table: item; date; local start/end time; time zone as printed; location/code; supplier; deadline or check-in rule; source label; status.
2. One chronological itinerary grouped by local calendar date.
3. A conflicts and tight-connections list.
4. A verification checklist limited to details that could cause lost money, missed transport, or denied entry.
5. A short list of facts you deliberately did not assume.

SOURCE PACK
[Paste redacted blocks labeled Source A, Source B, Source C...]
Step 04

Run a separate mismatch audit

A polished timeline can hide a copied AM/PM error or a time-zone jump. Keep the source pack in the conversation and ask for an audit that returns only mismatches plus a corrected timeline. One bundled audit spends one request.

Mismatch audit prompt
Audit your previous itinerary strictly against my labeled source blocks.

Check, in this order: calendar date; AM/PM; local time; printed time-zone label; airport or station code; terminal; address; cancellation deadline; check-in window; baggage rule; connection duration.

Return only:
A. A mismatch table with Previous value | Source value | Source label | Correction.
B. The corrected itinerary.
C. Items still marked [MISSING] or [CONFLICT].

Do not add web facts, estimates, transit times, entry rules, opening hours, or recommendations.
Step 05

Add dated official facts as a new layer

Open the airline, rail operator, hotel, border authority, or relevant government advisory yourself. Paste a short excerpt with its URL and the time you checked it. This is safer than asking the model to remember a schedule or entry rule. OpenRouter’s web-search plug-in can add cost even when the selected model is free, so it is not part of this $0 workflow.

Official update prompt
OFFICIAL UPDATE
Source organization: [name]
Source URL: [URL]
Checked at: [date, time, time zone]
Applies to: [flight/train/hotel/destination]
Exact excerpt: [paste only the relevant official text]

Compare this update with the checked itinerary. Return:
1. Changed or conflicting items only.
2. The exact itinerary rows that need revision.
3. Actions I must take, each linked to the supplied source URL.

Treat the excerpt as dated information. Do not extend it to claims the excerpt does not make.
Step 06

Export a trip sheet that works offline

Copy the checked itinerary into a document and print it to PDF. Put the last-checked time beside every live item. Save the PDF locally, share it with a travel companion, and keep official supplier apps for status changes.

  • Download your destination in an offline map before departure. Organic Maps is a free, open-source option on iOS and Android; its map data can still be incomplete.
  • Save the hotel address and first transfer in plain text, not only behind a login.
  • Set calendar alerts for check-in and cancellation deadlines after comparing each one with the original confirmation.
  • Recheck the official itinerary and relevant advisory on departure day.
Read before relying on it

What breaks

The cap: request 51 in the current UTC day can return HTTP 429. The daily window restarts at 00:00 UTC; upstream free capacity may fail earlier. Wait, retry later, or choose a paid route deliberately.

The tier boundary: T0 means no trial clock, no card, and no automatic overage on the free plan. Buying at least $10 in credits raises the free-model daily cap to 1,000, but that is a paid choice, not part of this guide.

The model: the Free Models Router can pick a different model per request. Output quality, latency, context handling, and availability vary. Keep the source ledger so a weaker answer is obvious.

The facts and privacy: a language model can miscopy or fabricate. Never use it as the final authority for live status, visas, safety, or entry. OpenRouter does not retain prompt text by default, but upstream provider policies vary; redact sensitive travel data and review privacy settings.

Three things

Details that make the method safer

Reveal each point. These came from the quota, routing, privacy, and travel-source checks behind this guide.

01 · routing

Record the model name

The free router selects from changing capacity and shows which model answered. Record that name beside the export; if a revision suddenly changes style or misses fields, you know the responder may have changed.

02 · quota

Batch corrections by UTC day

The 50-request cap is account-wide for free variants, not 50 per model. A source pack, one audit, and one official update use three requests; many tiny follow-ups burn the same pool.

03 · source sweep

Bring the official update to the model

The web-search plug-in can cost extra even with a free model. Paste a dated excerpt from the carrier or relevant government advisory instead, and keep its URL in the trip sheet.
