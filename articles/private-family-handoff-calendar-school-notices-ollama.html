What the local boundary changes

            
When you run the local qwen2.5:7b model, the prompt is processed by the model on your machine. Do not select an Ollama :cloud tag when the goal is local-only handling.

            
That boundary removes the hosted request meter, but it does not make model output reliable by itself. The prompt below forces dates, owners, source quotes, collisions, and unknowns into separate fields so you can check the result against the original notice.

Contrarian correction · rarity device

          
Most guides tell you to ask for a clean family calendar first. That is backwards.

          
For school notices, the costly failure is a polished schedule with a hidden collision. Ask the local model to find conflicts, missing owners, and uncertain dates before it formats a weekly view. Formatting first makes a wrong answer look finished.

          
    
            
  • Do not start with: “Make me a nice family calendar.” That request rewards neatness even when the source has two different pickup times.
    • 
            
  • Start with: “List every event, quote its source, find overlaps, and put unknowns in NEEDS CONFIRMATION.” That gives you a short review queue before the calendar.
    • 
            
  • Consequence: a five-minute source check can catch a duplicated pickup or an invented date before it reaches a shared calendar.
    •

Make the source text checkable before asking for a calendar.

            
Paste the text of one planning window, usually one week. Keep the date, time, location, and source label together. Replace real names with stable labels if other people will see the prompt or saved transcript.

            

              
    
                
  • Label each block SCHOOL, PARENT A, PARENT B, or ACTIVITY.
    • 
                
  • Write the timezone and the rule for ambiguous phrases such as “next Friday.”
    • 
                
  • Redact addresses, student IDs, medical details, and phone numbers that the schedule does not need.

2 of 4 · preserve evidence

          


          

            
Run the conflict-first prompt, not a calendar prompt.

            
The output order is intentional: source ledger, conflicts, unknowns, then a proposed handoff table. A model can make a wrong schedule look authoritative when the audit and the formatting happen in one vague request.

            

              
    
                
  • Copy the complete template below or use the live sandbox above.
    • 
                
  • Require a source quote for every date and owner; missing evidence goes into NEEDS CONFIRMATION.
    • 
                
  • If the calculator crosses 80% of 32K context, split the bundle before running it.
    • 
              

              

                
conflict-first prompt

                
You are a family schedule auditor, not an authority.
Use only the source blocks below.

Rules:
1. Preserve exact dates, times, locations, and timezone.
2. Quote the source block for every extracted event.
3. Never infer a date, owner, travel time, or agreement.
4. Find overlaps, impossible handoffs, missing owners, and contradictions first.
5. Put uncertain fields in NEEDS CONFIRMATION.
6. Only after the audit, draft a proposed weekly handoff table.

Return these headings in order:
A. SOURCE LEDGER
B. CONFLICTS AND OVERLAPS
C. NEEDS CONFIRMATION
D. PROPOSED HANDOFF TABLE
E. CHECKS I MUST PERFORM

SOURCE BLOCKS:
[paste one planning window here]

              

            

            
3 of 4 · find the expensive mistakes first

          


          

            
Verify each event before it becomes a shared plan.

            
The model's output is a draft, not a calendar authority. Compare each row with the source block, resolve the confirmation list with the people involved, and only then copy the final rows into the calendar your household already uses.

            

              
    
                
  • Check every date, time, location, and owner against the original notice.
    • 
                
  • Ask a person to resolve every item in NEEDS CONFIRMATION; do not let the model fill the gaps.
    • 
                
  • Share the final calendar, not the raw family messages or the unreviewed model output.
    •

Durable framework

            
1. Preserve evidence. Put the source beside every event.

            
2. Audit before formatting. Find collisions, unknowns, and owners before making the result attractive.

            
3. Keep a human checkpoint. The model can draft a plan; a person must confirm the plan.

            
4. Treat facts as dated. The model size, context window, software behavior, and hosted prices can change; recheck the chips marked “as of 2026-08-20.”
